# Node-RED 侧改造：让「预期结果」也广播给自动化程序

## 为什么会收不到（根因）

你的流程是**一问一答**结构：

```
被测程序 ──命令(READER_GET_BY_MRZ/serial等)──> Node-RED [websocket in 接收程序消息]
                                                   │
                                          [解析消息] → [switch command]
                                                   │
                                          [根据serial查找] → [switchCommand]
                                                   │
                                          [返回预期结果]  ← 组装成 gate.capture JSON
                                                   │
                                          [websocket out 发送给程序]
                                                   │
                                        ──> 只回给「发命令的那个客户端」= 被测程序
```

关键在 Node-RED 的 WebSocket 节点对：**`websocket in` 会给消息打上 `msg._session`**
（发起方那条连接的标识）。`websocket out`（`Listen on` 模式）看到消息带 `_session`，
就**只发回给那条连接**，而不是广播。

所以：被测程序（它发的命令）能收到；我们和 APIPost（只是连上来听、没发过命令）
永远收不到——和现象完全一致。

## 改法一：在「返回预期结果」里加一行（最小改动）

双击 `返回预期结果` 这个 function 节点，在 `msg.payload = JSON.stringify({...});` **之后**加一行：

```js
delete msg._session;
```

然后 Deploy。就这一行：消息不再定向回复，而是**广播给连在 `/` 上的所有客户端**。
被测程序照旧收到（广播包含它），本自动化程序也能收到。

> 拆成独立节点也行：在 `返回预期结果` 和 `发送给程序` 之间插一个
> **change** 节点，规则 `删除 msg._session`。效果完全一样，好处是能手点禁用/回滚。

## 改法二：直接导入改好的流程

`docs/nodered/flows-广播改造.json` 就是你那份 `flows.json` 的改造版
（8 个节点、id 全部不变，**只有「返回预期结果」这一个节点不同**：
多了 `delete msg._session;`，状态文字顺手把"发送逾期结果"改成"发送预期结果（广播）"）。

Node-RED 菜单 → 导入 → 选这个文件 → **选"导入到当前流程"** → Deploy。
导入会按 id 更新同 id 的节点，不会重复建节点。

## 你的报文格式已经和本程序协议一致 ✅

`返回预期结果` 组装的正是本程序的 `gate.capture` 协议：

| 本程序字段 | 你的取值 |
| --- | --- |
| `case_id` | `msg.docData.DocNum` |
| `expected.allow_pass` | `msg.docData.AllowPass` |
| `expected.failed_node` | `msg.docData.FailedNode` |
| `capture.cert_no` | `msg.serial` |
| `capture.passenger_name` | `msg.docData.PassengerName` |
| `capture.photo_base64` | `msg.docData.CHIPFace` |

**所以 `gate.field_map` 不需要配。**

### 但有两点建议核对

1. **`cert_no` 填的是 `msg.serial`**。本程序靠 `capture.cert_no` / `passenger_name`
   去匹配日志里的 `旅客[xxx]`。如果日志里的 `旅客[...]` 是**证件号**而不是 serial，
   就把 `cert_no` 换成证件号字段（例如 `msg.docData.DocNum`），否则会匹配不上。
   兜底：`run.single_session_fallback: true`（只有一个候选会话时仍能归属）。
2. **`allow_pass` 的取值格式**。本程序认 `true/false`、`"true"/"false"`、`1/0`、
   `"允许"/"不允许"`、`"pass"/"deny"`。如果 `AllowPass` 是 `"Y"/"N"` 之类，
   需要改流程（`AllowPass === "Y"`）或者在配置里告诉我，我再加判定词。
